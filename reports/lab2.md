## 问题1、恢复sys_get_time
    首先回顾一下上一章是如何实现该功能的，传入一个pub struct TimeVal {    pub sec: usize,    pub usec: usize,}，再调用riscv::register::time::read()，从控制状态寄存器中读取时间。
问题在于，用户传入的TimeVal变量的指针指向的是用户的虚拟地址空间，而系统调用发生在内核态是内核的虚拟地址空间，无法直接赋给用户程序中指针的地址，因此需要用地址翻译功能找出用户指针指向的真正物理地址是什么然后把值放入真正的物理地址中。
### 那么要如何从用户地址转为物理地址呢？
    参考系统调用中写入的相关改进，参考translated_byte_buffer接口，
    1、首先每个应用程序都独占一个页表，要先把该变量的指针指向的虚拟页号转为物理页号，
    2、调用task中的current_user_token接口可以获得用户虚拟页表中根页表的物理地址。
    3、从根页表中获得实际的物理页，把物理页和页内偏移相加获得实际物理地址。
    4、是否会存在跨页现象？为了避免跨页写入，因此直接逐字节写入。
### 如何检测用户是否有权限访问？查询页表项中的权限位

    2、读写的功能是把ptr视为一个u8指针，然后返回该地址的值，因此要把该ptr转为实际的物理地址再读取或写入即可。

## 问题3、实现mmap和munmap
    1、根据观察，任务管理器中任务控制块有分配地址空间的功能，因此给MemorySet结构体新增一个带冲突检测的映射虚拟页的方法，查询每一个内存空间是否冲突，如果没有的话就插入。
    2、如果要取消映射，因为要每一个虚拟页都要取消，因此进行逐页unmap，遍历每一个内存区域，如果发现当前虚拟页存在该内存区域，就取消当前虚拟页的映射，接着遍历下一个虚拟页。

## 问答作业
### 1、请列举 SV39 页表页表项的组成，描述其中的标志位有何作用？
    [53~10]是物理页号，[7~0]是标志位。仅当 V(Valid) 位为 1 时，页表项才是合法的；R/W/X 分别控制索引到这个页表项的对应虚拟页面是否允许读/写/取指；U 控制索引到这个页表项的对应虚拟页面是否在 CPU 处于 U 特权级的情况下是否被允许访问；G 我们不理会；A(Accessed) 记录自从页表项上的这一位被清零之后，页表项的对应虚拟页面是否被访问过；D(Dirty) 则记录自从页表项上的这一位被清零之后，页表项的对应虚拟页表是否被修改过。

### 2、缺页
#### （1）缺页指的是进程访问页面时页面不在页表中或在页表中无效的现象，此时 MMU 将会返回一个中断， 告知 os 进程内存访问出了问题。os 选择填补页表并重新执行异常指令或者杀死进程。
    请问哪些异常可能是缺页导致的？
    答：缺页异常（Page Fault）， TLB 失效（TLB Miss/Invalidation）
    发生缺页时，描述相关重要寄存器的值，上次实验描述过的可以简略。
    答：stval（Supervisor Trap Value Register）作用：保存触发缺页的 虚拟地址，scause（Supervisor Cause Register）作用：记录缺页原因
#### （2）缺页有两个常见的原因，其一是 Lazy 策略，也就是直到内存页面被访问才实际进行页表操作。 比如，一个程序被执行时，进程的代码段理论上需要从磁盘加载到内存。但是 os 并不会马上这样做， 而是会保存 .text 段在磁盘的位置信息，在这些代码第一次被执行时才完成从磁盘的加载操作。
    这样做有哪些好处？
    答：提高打开程序的速度，提高内存利用率。
#### （3）其实，我们的 mmap 也可以采取 Lazy 策略，比如：一个用户进程先后申请了 10G 的内存空间， 然后用了其中 1M 就直接退出了。按照现在的做法，我们显然亏大了，进行了很多没有意义的页表操作。
    处理 10G 连续的内存页面，对应的 SV39 页表大致占用多少内存 (估算数量级即可)？
    答：一个页表4096字节，一个页表项为usize类型在64为系统中占8字节，因此一个页表能放4096/8=512个页表项。一个页表项指向一个物理页为4096字节=4KB, 因此一个页表能放512*4KB = 2MB大小的物理页。SV39为三级页表，一个二级页表能放512个三级页表，因此一个二级页表能放512*2MB = 1GB大小的物理页。10个G就需要十个二级页表，因此页表占用的内存大小为10*8字节 + 10个物理页 ≈ 40KB。
    请简单思考如何才能实现 Lazy 策略，缺页时又如何处理？描述合理即可，不需要考虑实现。
    答：当用户申请内存后，虚拟地址不立即映射到物理地址，而是存起来，等到用户访问某个页发生缺页异常时，检测缺页是否在用户申请的内存中，如果不在，就直接杀死进程。如果在，就载入该页，然后返回异常指令重新执行。
    缺页的另一个常见原因是 swap 策略，也就是内存页面可能被换到磁盘上了，导致对应页面失效。此时页面失效如何表现在页表项(PTE)上？
    答：PTE最低位是有效位，为0时代表页面失效。第8到9位是保留位，可以给操作系统自定义使用，可用于标记交换页。

### 3、双页表与单页表:为了防范侧信道攻击，我们的 os 使用了双页表。但是传统的设计一直是单页表的，也就是说，用户线程和对应的内核线程共用同一张页表，只不过内核对应的地址只允许在内核态访问。 (备注：这里的单/双的说法仅为自创的通俗说法，并无这个名词概念，详情见 KPTI )
    在单页表情况下，如何更换页表？
    答：在x86架构中，CR3 寄存器：存储当前进程的 页表基地址（PML4/PDPT 的物理地址），切换 CR3 即切换页表。
    单页表情况下，如何控制用户态无法访问内核页面？
    答：页表项有用户权限位，将用户权限位设置为0即可。
    单页表有何优势？
    答：每次切换程序无需切换页表，高并发时性能好。
    双页表实现下，何时需要更换页表？假设你写一个单页表操作系统，你会选择何时更换页表（回答合理即可）？
    答：双页表时，每个用户程序和内核都有自己的页表，运行不同的程序时就要切换不同的页表。如果是单页表，大部分情况下无需 切换页表，仅在启动时可能会切换，或更换内存后需要切换页表。
