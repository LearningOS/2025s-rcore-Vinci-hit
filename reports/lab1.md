# 实验相关问题解答

## 新增 trace 系统调用
想要新增题目中的 trace 系统调用是很简单的。只需在任务管理器里添加一个二维数组，用于统计每个任务的系统调用次数。每次调用 `syscall` 时，在任务管理器中当前任务对应的统计数组位置加 1 即可。由于任务管理器已实现多线程互斥访问，所以无需修改代码。

### 2. 深入理解 trap.S 中两个函数 __alltraps 和 __restore 的作用，并**回答**如下问题:

L40：刚进入 __restore 时，sp 代表了什么值。请指出 __restore 的两种使用情景。

L43-L48：这几行汇编代码特殊处理了哪些寄存器？这些寄存器的的值对于进入用户态有何意义？请分别解释。

ld t0, 32*8(sp)
ld t1, 33*8(sp)
ld t2, 2*8(sp)
csrw sstatus, t0
csrw sepc, t1
csrw sscratch, t2
****回答****：
刚进入时1、从内核态返回用户态，sp存着内核态的指针，最后切换为用户态指针。2、在初始化任务管理器时载入任务上下文，刚进入时sp存着每个任务在初始状态下的上下文在栈中的指针。
因为0~31是普通寄存器，
32是控制状态寄存器sstatus其中SPP 等字段给出 Trap 发生之前 CPU 处在哪个特权级（S/U）等信息。
33控制寄存器是sepc 会被修改为 Trap 处理完成后默认会执行的下一条指令的地址，用于恢复用户态程序。
2号寄存器（从零开始算）是栈指针地址寄存器即sp，存储着用户sp的地址，放入sscratch中备用。

### 3、L50-L56：为何跳过了 x2 和 x4？

ld x1, 1*8(sp)
ld x3, 3*8(sp)
.set n, 5
.rept 27
   LOAD_GP %n
   .set n, n+1
.endr

**回答**：x2是sp，只有所有内容都结束了才能在最后从sscratch中交换获得。
x4是线程指针寄存器，用于多线程编程，指向当前线程的特定数据区域。

### 4、L60：该指令之后，sp 和 sscratch 中的值分别有什么意义？

csrrw sp, sscratch, sp
**回答**：该指令相当于交换了sscratch中的值和sp的值，从上上题可得sscratch中存储着用户程序的栈指针现在转移到sp为执行用户程序做准备，而当前sp保存着内核栈的栈指针转移到sscratch寄存器为下次进入内核态做准备。

### 5、__restore：中发生状态切换在哪一条指令？为何该指令执行之后会进入用户态？
**回答**：而当 CPU 完成 Trap 处理准备返回的时候，需要通过一条 S 特权级的特权指令 sret 来完成，这一条指令具体完成以下功能：
CPU 会将当前的特权级按照 sstatus 的 SPP 字段设置为 U 或者 S ；
CPU 会跳转到 sepc 寄存器指向的那条指令（sepc中存着用户程序将要执行的下一条指令（陷入前）），然后继续执行。

### 6、L13：该指令之后，sp 和 sscratch 中的值分别有什么意义？

csrrw sp, sscratch, sp
**回答**：执行后，用户程序栈指针会放入sscratch，sp从sscratch中获得内核栈指针。

### 7、从 U 态进入 S 态是哪一条指令发生的？
当发生系统调用ecall或发生其它异常时，硬件会自动完成如下这些事情：
sstatus 的 SPP 字段会被修改为 CPU 当前的特权级（U/S）。
sepc 会被修改为 Trap 处理完成后默认会执行的下一条指令的地址。
scause/stval 分别会被修改成这次 Trap 的原因以及相关的附加信息。

CPU 会跳转到 stvec 所设置的 Trap 处理入口地址，并将当前特权级设置为 S ，然后从Trap 处理入口地址处开始执行。
